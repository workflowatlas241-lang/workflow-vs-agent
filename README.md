# Workflow vs Agent — same-ticket comparison (reproducible, free)

Runs three designs on the **same frozen support-ticket questions** using your
**local Ollama** model, and records real numbers. No API keys, no cost.

- **W** workflow — a router picks a known intent; code runs that intent's fixed tool sequence; the model writes the reply. `"other"` → handoff.
- **A** agent — the model gets all tools and chooses what to call, in what order.
- **H** hybrid — same router; known intents take W's fixed path, `"other"` goes to the agent loop (read-only).

## 1. Prerequisites (one time)

1. Ollama running: `ollama serve`
2. Pull a small model: `ollama pull qwen2.5:3b`
   (Any model with tool-calling works; bigger = slower but better.)

## 2. Run it

```bash
cd experiments/workflow-vs-agent

# full run (3 seeds × 12 questions × 3 designs = 108 conversations)
python run_experiment.py --model qwen2.5:3b --seeds 3

# fast sanity check (1 seed = 36 conversations, ~1-2 min)
python run_experiment.py --quick
```

## 3. What you get

- **`results.json`** — the aggregated table (success/wrong/handoff/routing-error + calls/tokens/latency per design).
- **`runs/`** — one transcript per conversation, so you can read **every model response verbatim**.

## 4. How to make sure you are NOT being fooled

The numbers are generated by **your** machine, not by me. Four checks:

1. **You run it.** I never see your results unless you paste them. The script calls
   `http://127.0.0.1:11434` — your local Ollama. Nothing leaves your machine.
2. **Read the transcripts.** Open `runs/*.json` — the `transcript` field holds the
   exact messages and tool calls. If an answer looks wrong, you can see the exact
   reasoning and tool result that produced it.
3. **The dataset is frozen + hashed.** The script prints `dataset SHA256 (first 16)`.
   Re-run and confirm the hash is identical — if it ever changed, the questions
   (or data) were edited after a result.
4. **Re-run to reproduce.** Same seed + same model → same outcome. Run
   `--quick` twice; the results must match.

## 5. How to read the results honestly

- `success` = the answer contained every required fact (the data the model had to retrieve).
- `wrong` = missing a required fact (see `missing_facts` in the run JSON).
- `handoff` = workflow/hybrid routed to `"other"` (a legitimate outcome, not a failure).
- `routing_error` = known question, router picked the wrong intent (counted separately — a real workflow failure mode).

**Do not cherry-pick.** Report all four columns. A negative result (e.g. "the agent
hallucinated on Q9") is worth more trust than a clean sweep.

Once you have `results.json`, fill the empty "same-ticket worksheet" in the post
with these real numbers, and replace the honesty disclaimers with a one-line
